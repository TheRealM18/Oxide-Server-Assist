# Plugin icon set for Server Assist

Hand-painted, post-apocalyptic UI icons for the companion plugins that render
inside the Server Assist window. They replace the generic
`ui_game_symbol_hammer` placeholder that a card falls back to, so AdminKits,
AdminShop, AdminSuite and the rest each get their own recognizable art.

These are **plugin** icons, not Server Assist branding. The set is intentionally
built around the plugin subjects: kits, shops, staff tools, auctions, rewards,
backpacks, permissions, reloads, votes and the pack bootstrap.

Every icon is original art generated for this pack. Use it on your server,
streams, wiki and mod packs without attribution.

## What is in here

```text
ServerAssistArt/
  icons/                     high-resolution masters (mixed sizes, transparent)
    _sheets/                 2x2 source sheets for the Admin Tools batch
  bonus/                     optional Server Assist mark (not part of the set)
  preview/                   256x256 previews (generated)
  UIAtlases/UIAtlas/         128x128 game-ready PNGs (generated)
  contact-sheet.png          labelled overview of the finished icons
  tools/build-icons.ps1      rebuilds previews, atlas PNGs and the contact sheet
  tools/slice-sheet.ps1      splits a 2x2 sheet into four masters
  README.md                  this file
  PLANNED_ICONS.md           future icon batches
  VOTESKIPNIGHT_ICON_REQUEST.md  four requested VoteSkipNight icons (not rendered)
```

The `icons/` folder is the source of truth. Everything else is generated by
`tools/build-icons.ps1`; run it again if you add or change a master.

## Install the PNGs

The icons are client-side. They live in the **Server Assist mod folder** on the
server and on every client, because the Server Assist client window is what
draws every plugin card.

1. Stop the server and the game.
2. Copy the `UIAtlases` folder from this pack into the Server Assist mod folder:

   ```text
   Mods/AA0_ServerAssistMod/
     ModInfo.xml
     ServerAssistMod.dll
     Config/
     UIAtlases/
       UIAtlas/
         sa_admin_kits.png
         sa_admin_shop.png
         sa_admin_suite.png
         sa_auction_house.png
         sa_daily_rewards.png
         sa_dynamic_backpack.png
         sa_permission_gui.png
         sa_plugin_hot_reload.png
         sa_vote_skip_night.png
         sa_qln_pack.png
         sa_nav_*.png
         sa_act_*.png
   ```

3. Start the server and a client. The game bakes the PNGs into `UIAtlas` at
   launch; there is no registration step and no XML edit.

If a card still shows the hammer, the client is missing the PNG or the sprite
name is misspelled. Sprite names never include `.png`.

> The icon element in `Config/XUi_InGame/windows.xml` uses the default atlas,
> which is `UIAtlas`, so no XML change is needed. If you later set
> `atlas="ItemIconAtlas"` on the card icon element, put the PNGs in
> `UIAtlases/ItemIconAtlas/` instead and use the same sprite names.

## Applying the icons

The plugin-card keys are already passed at registration:

- AdminKits, AdminShop, AdminSuite, DailyRewards, PermissionGui and
  VoteSkipNight call `SetPanelIcon` after `RegisterGuiHook`.
- DynamicBackpack and PluginHotReload call `RegisterPanel` with the icon.
- AuctionHouse calls `SetProviderIcon` after `RegisterGuiProvider`.

The Admin Tools `sa_nav_*` and `sa_act_*` icons are wired into AdminSuite's
screens, rows and buttons. PermissionGui reuses them on matching permission
nodes.

AdminKits also reuses the finished `sa_nav_*`, `sa_act_*` and plugin-card icons
for its panel, screen banners, kit-state rows, item rows and action buttons while
the planned `sa_kits_*` set is unrendered. The exact mapping lives in
`AdminKits/ICONS.md` next to the AdminKits plugin. The focused seven-icon
follow-up request is in `REQUESTS_AdminKits.md`; only those seven are needed,
not the kit-category icons.

For a new custom panel, pass the sprite key through `RegisterPanel`:

```csharp
ServerAssist.Call(
    "RegisterPanel",
    "example",                         // hook id
    "Example",                         // label
    "What the panel does.",            // description
    "example.use",                     // permission
    "ExamplePlugin",                   // plugin name
    "HandleGuiRequest",                // handler method
    "sprite:sa_nav_players",           // icon
    10);                               // order
```

For a provider, call `SetProviderIcon(providerId, icon)` after
`RegisterGuiProvider`.

To use any icon on a button without touching code, create a shared button in
Server Assist, choose **Edit Icon**, and paste the key, for example
`sprite:sa_act_ban`. `Find Item Icon` still works for live item icons.

## Format notes

- 128x128, 32-bit ARGB PNG with a transparent background.
- Each master is auto-trimmed and re-centered with a 4 px margin, so icons look
  optically consistent at 64x64 even though the subjects have different shapes.
- The card draws the sprite at 64x64. 128x128 gives clean scaling on high-DPI
  and 4K UI scales without a visible pixel grid.
- Masters are 1254x1254 for the plugin cards and 626x626 for the Admin Tools
  quadrants, which is plenty for the wiki, Discord, thumbnails and print.

Rebuild after adding a master:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-icons.ps1
```

## Hosting on Google Drive

Google Drive is fine for distributing the pack, but keep the two jobs separate:

**For players (this is what makes the icons work in game)**
Upload a zip of the whole Server Assist mod folder, now including `UIAtlases/`,
to Drive. Set the file to **Anyone with the link -> Viewer**, then use that
link in your mod pack. If you use QLNPack, replace the Server Assist zip in the
pack folder, rebuild the manifest and update its SHA-256. Never point the game
at a raw Drive image link; the game only loads PNGs from the local mod folder.

**For previews and documentation**
Upload `contact-sheet.png` and the files in `preview/` as normal Drive files if
you want to show the set off. Drive's preview works well for PNGs of this size.

Drive-specific tips:

- Keep filenames stable (`ServerAssist-2.0.0.zip`, `sa_admin_kits.png`). A
  renamed file gets a new Drive ID and every old share link breaks.
- Upload the zip, not a folder. Folder links are not stable download targets for
  launchers and bootstrap tools.
- Do not re-encode the PNGs through a screenshot or a chat app. The alpha
  channel is what keeps the icons from showing a dark box on the card.
- If Drive shows "Preview is not available" for a zip, that is normal. The
  download still works.
- Google Drive direct links change format over time. For QLNPack, always run
  the pack's `build-manifest-from-urls.ps1` or `match-drive-links.ps1` after
  uploading, rather than hand-editing URLs.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Hammer still shows | Client lacks the PNG, name is wrong, or the hook still uses the default icon | Check `Mods/AA0_ServerAssistMod/UIAtlases/UIAtlas/sa_*.png`; sprite name has no `.png`; pass the icon through `RegisterPanel` or use a shared button |
| Icon is a plain white square | Alpha lost during re-encode | Re-copy from this pack, do not screenshot |
| Icon is dark or invisible | `IconTint` has a low alpha | Clear `IconTint` or use a full-alpha color |
| Icon appears on one client only | Mods folder differs between clients | Install the same mod folder everywhere |
| Icon name collides with another mod | Another mod uses the same PNG name | Keep the `sa_` prefix |
