# Server Assist Art

> **Version:** 1.3.0 (art pack) · **Type:** client-side UI atlas / icon pack · **Source:** [ServerAssistArt](https://github.com/TheRealM18/Oxide-Server-Assist/tree/main/ServerAssistArt)

Server Assist Art is the hand-painted icon set for the companion plugins that
render inside the Server Assist window. The icons replace the generic
`ui_game_symbol_hammer` placeholder so kits, shops, staff tools, auctions,
rewards, backpacks, permissions, reloads, votes and the pack bootstrap each get
recognizable art.

These are **plugin** icons, not Server Assist branding. `sa_server_assist.png` is
an optional field-radio mark for the launcher itself and is not part of the plugin
set.

Every icon is original art generated for this pack. Use it on your server,
streams, wiki and mod packs without attribution.

---

## Requirements

| Requirement | Detail |
|---|---|
| Client | 7 Days to Die V3.4.x, EAC off |
| Server Assist | Client mod 2.x on the server and every client that draws the board |
| Install location | `Mods/<Server Assist folder>/UIAtlases/UIAtlas/` or a separate atlas mod |
| Build tools | Windows PowerShell 5.1+ with `System.Drawing` |
| Source editing | Any image editor that preserves 32-bit alpha |
| Runtime | No plugin, no DLL, no XML registration |

The PNGs are client assets. The game bakes every mod's
`UIAtlases/UIAtlas` folder into the global `UIAtlas` at launch. There is no
manifest and no XML edit.

!!! warning
    Sprite names are **not namespaced by mod**. Every mod contributes to the
    same atlas, so keep the `sa_` prefix. A generic `admin_shop.png` from another
    mod could collide with an unprefixed name.

## Install the PNGs

### Option A — inside the Server Assist mod

1. Stop the server and the game.
2. Copy the `UIAtlases` folder into the Server Assist mod folder:

   ```text
   Mods/AA0_ServerAssistMod/
     ModInfo.xml
     ServerAssistMod.dll
     Config/
     UIAtlases/
       UIAtlas/
         sa_*.png
   ```

3. Start the game. The atlas is baked at launch; no registration step and no
   XML edit are needed.

### Option B — separate art mod

Ship the atlas as its own client mod, commonly `AAZ_ServerAssistArt`, so it loads
after the Server Assist folder. The current release package is
`AAZ_ServerAssistArt-1.3.0`. Clients that use the separate pack still need the
Server Assist client mod; the art folder only supplies sprites.

### Atlas target

The card icon element in `Config/XUi_InGame/windows.xml` uses the default
`UIAtlas`. If you later set `atlas="ItemIconAtlas"` on the icon element, put the
PNGs in `UIAtlases/ItemIconAtlas/` instead and use the same sprite names.

Sprite references never include `.png`.

## Format and build tooling

### Format

- Atlas: **128x128**, 32-bit ARGB PNG, transparent background.
- Preview: **256x256** ARGB PNG.
- Card draw size: **64x64**.
- Masters: 1254x1254 for plugin cards and 626x626 for Admin Tools quadrants.
- Each master is auto-trimmed to visible pixels and re-centered with a 4 px
  margin so differently shaped subjects look optically consistent at 64x64.

### `tools/build-icons.ps1`

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-icons.ps1
```

The script:

1. Reads every PNG in `icons/`.
2. Uses the preferred order for the contact sheet, then appends any new master
   alphabetically.
3. Prefixes `sa_` when a master does not already start with it.
4. Finds the visible bounding box using alpha `> 8`.
5. Fits the trimmed image into a 128x128 atlas cell with 4 px padding.
6. Writes a 256x256 preview with 10 px padding.
7. Builds `contact-sheet.png` as a 4-column grid of 300 px cells with a 44 px
   label band.

Outputs:

```text
UIAtlases/UIAtlas/<sprite>.png
preview/<sprite>.png
contact-sheet.png
```

The script requires Windows PowerShell 5.1+ because it uses `System.Drawing`.

### `tools/slice-sheet.ps1`

The Admin Tools batch was generated as six 2x2 sheets in `icons/_sheets/`. Split
a sheet into four masters:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\slice-sheet.ps1 `
  -Sheet .\icons\_sheets\admin_nav_1.png `
  -OutDir .\icons `
  -Names sa_nav_players,sa_nav_moderation,sa_nav_teleport,sa_nav_items
```

The script requires exactly four output names, splits at the half-width and
half-height, and writes one PNG per quadrant. Run `build-icons.ps1` afterwards.

### Style brief

The shared style is a 7 Days to Die post-apocalyptic UI icon: hand-painted
weathered metal, chipped teal paint, rust, scratches, bold dark outline, strong
rim light, high contrast, chunky readable silhouette, slightly isometric
three-quarter view, centered, no text, fully transparent background.

For Twitch sprites, the request explicitly forbids platform branding: no Twitch
purple, no glitch logo, no "TTV", no Prime crown. Status tints must stay
readable, so keep the art mostly neutral metal/teal/amber.

## Integration with plugins

| Plugin pattern | Call |
|---|---|
| Home-row panel | `RegisterPanel(..., "sprite:sa_nav_players", order)` |
| GUI hook | `SetPanelIcon(id, "sprite:sa_admin_shop")` after `RegisterGuiHook` |
| Provider | `SetProviderIcon(providerId, icon)` after `RegisterGuiProvider` |

```csharp
ServerAssist.Call(
    "RegisterPanel",
    "example",                  // panel id
    "Example",                  // label
    "What the panel does.",     // description
    "example.use",              // permission
    "ExamplePlugin",            // plugin name
    "HandleGuiRequest",         // handler method
    "sprite:sa_nav_players",    // icon
    10);                        // order
```

The provider icon is also the default background and banner when the provider
view omits `background` and `banner`.

Any icon can be used without code: create or edit a shared button, choose
**Edit Icon**, and paste the key (for example `sprite:sa_act_ban`). `Find Item
Icon` remains the live item picker. A hook or provider view can set
`background=sprite:sa_admin_shop` and `banner=sprite:sa_admin_shop`;
`background` is a low-opacity watermark and `banner` is a 72x72 header image.
Server Assist fills both from the registered panel icon when the view does not
set them.

### Live icon read-back

TwitchIntegration uses these role forms:

| Role form | Resolution |
|---|---|
| `plugin:AdminSuite` | `GetPluginIcon("AdminSuite")` |
| `panel:somepanel` | `GetPanelIcon("somepanel")` |
| `sprite:name`, `item:name`, `atlas:atlasName:sprite` | Same syntax as buttons |
| `none` | Vanilla fallback |

If the target plugin or panel is not loaded, the role falls back to its built-in
static sprite. That is why AdminSuite, PermissionGui and PluginHotReload do not
need Twitch-specific textures.

## Server Assist integration

The art pack is consumed entirely through the Server Assist rendering path:

- The client resolves `sprite:` and `atlas:` keys against the loaded atlases.
- Panel cards, provider cards, row icons and action buttons all use the same
  syntax.
- `RegisterPanel` / `SetPanelIcon` / `SetProviderIcon` attach the icon to the
  panel metadata; the server automatically uses it for missing `background` and
  `banner` fields.
- The client falls back to `ui_game_symbol_hammer` when a sprite is missing.

No companion plugin ships its own XUi window or client DLL for these icons.
The Server Assist client is the only renderer.

See [Icons and art](../../core/icons.md) for the generic icon syntax and
[Server Assist Mod](../client/server-assist-mod.md) for the client folder.

## Typical workflows

**Add or replace an icon.** Render the master to `icons/sa_<name>.png`, run
`tools/build-icons.ps1`, confirm `UIAtlases/UIAtlas/sa_<name>.png`, then point
the panel, provider, row or button at `sprite:sa_<name>`. Keep sprite names
stable when replacing art; configs store keys, not paths.

**Ship through the QLN pack.** Copy `UIAtlases/UIAtlas` into the Server Assist
mod folder (or the separate art mod folder), update the pack entry's `sha256`
and `size`, and let [QLN Pack Bootstrap](../client/qln-pack-bootstrap.md)
install it at restart.

**Build a preview sheet.** Run `build-icons.ps1` and use `contact-sheet.png` or
`preview/`. Resize from `icons/`, not from the 128x128 atlas copies, when you
need a different size.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Hammer still shows | Client lacks the PNG, sprite name is misspelled, or the card still uses the default | Check `UIAtlases/UIAtlas/sa_*.png`; remove `.png` from the sprite key; pass an icon at registration |
| Icon is a plain white square | Alpha lost during re-encode | Re-copy from the pack; do not screenshot or chat-compress |
| Icon is dark or invisible | Low-alpha `IconTint` | Clear `IconTint` or use a full-alpha color |
| Icon appears on one client only | Mods folders differ | Install the same Server Assist/art folder everywhere |
| Sprite name collides with another mod | Missing `sa_` prefix | Rename to `sa_<name>` and rebuild |
| New master does not appear | Build script not run | Run `tools/build-icons.ps1` |
| Build script fails | Windows PowerShell/System.Drawing unavailable | Run Windows PowerShell 5.1+ on Windows |
| Art pack loads but cards do not | Server Assist client mod missing | Install `ServerAssistMod.dll` and its config |

More: [Troubleshooting](../../reference/troubleshooting/index.md).
